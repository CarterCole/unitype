// NODE 0x02 — TYPE IDENTITY

UNITYPE

An H3 for types. Every type gets a canonical form, a content address computed from its structure alone, and three ordinary words you can say out loud.

>

01NAMES

Identity from structure, not from a name anyone chose.

H3 gives every hexagon on Earth a canonical ID that anyone can compute without asking anyone. unitype does it for types. Normalization gives each semantic type exactly one serialization, and a blake3 hash over those bytes is its identity — excluding names, prose and annotations, because none of those are what makes a type what it is.

So two systems that have never exchanged a schema can find out they hold the same type by comparing 32 bytes, and two people can find out by comparing a phrase.

geo::Point and gfx::Vec2 get the same three words because they hold the same data — which nobody told it. Types live in universes, and between universes nothing is compatible by accident: data crosses only through an explicit link that carries a witness anyone can read.

02PROPOSITIONS & PROOFS

Which implementation runs is a policy decision, not an architectural one.

A function signature is a proposition. An implementation of it is a proof. There can be many proofs of one proposition — compiled or interpreted, native or sandboxed — each declaring its own time and space cost. Both are checked against the signature at the boundary, so a proof that lies about what it proves is caught rather than trusted.

Same proposition, same answer. One ran in-process in Rust; the other ran in Python over a pipe.

A generic proposition is a claim about every type. A proof of reverse<T> cannot look at a T, so every T it returns must be one it was given — and conform checks that from the signature alone, with nobody writing down an expected answer. A proof that sorts when it sees integers is caught.

03INSTRUMENTS

The loop closes: a type can be described, checked, addressed, named, bridged, generated and computed — in more than one language. 735 tests, including the subtyping, inference and shape laws as property tests.

04TRY IT

05COMMITMENTS

The specification is normative, so this is implementable in any language. The Rust workspace is the reference, not the definition.

  1. Names are not identity.Two structs called User in different universes are unrelated until someone links them; two identically-shaped types with different names have the same address.
  2. Nothing crosses a universe boundary by accident.Subtyping stops at the boundary. Links are the explicit permission, and always carry a witness.
  3. Costs are declared, not measured.An implementation states its complexity and the dispatcher believes it; a differential harness checks that all proofs actually agree.
  4. A proof that lies is caught.Arguments and results are checked against the signature at the dispatch boundary, so a wrong shape fails loudly instead of propagating.
  5. Word aliases are for people.Derived, stable, and lengthening on collision like an abbreviated git hash — but ut1: addresses remain the authority.
  6. A type is an ordinary thing to compute with.A declaration is a value that validates, addresses and travels like any other, and a test keeps that description from drifting.
